# 校园网 ePortal 协议说明

## 网络探测

程序关闭 HTTP 自动跳转，依次访问以下探测地址，并按各自的标准响应判断联网状态：

所有请求均携带经当前门户实测可用的 Windows 浏览器 `User-Agent`；该门户在缺少此头时会返回 HTTP 200 空正文。接口空正文单独分类并有限重试，不跳过参数校验继续登录。

- `msftconnecttest.com/connecttest.txt`：状态码 200，正文精确等于 `Microsoft Connect Test`；
- `msftncsi.com/ncsi.txt`：状态码 200，正文精确等于 `Microsoft NCSI`；
- `connect.rom.miui.com/generate_204`：状态码 204；
- `detectportal.firefox.com/canonical.html`：状态码 200，正文包含 canonical 成功标记。

任意 HTTP 200 不代表已经联网。跳转到 ePortal，或返回通过 ePortal 特征校验的登录页，才进入认证流程。未知 HTML 返回警告并停止自动提交。重定向最多 5 次，并检测循环；单个响应最多读取 1 MiB。

## ePortal 请求序列

1. 请求探测发现的门户地址，保存本次流程独立的 Cookie。
2. 校验页面含 `AuthInterFace` 特征，并解析隐藏字段。
3. `POST InterFace.do?method=pageInfo`。
4. `POST InterFace.do?method=getServices&queryString=...`，请求体为空。
5. 从动态服务列表按显示名称匹配用户设置，提交其 `serviceName`。
6. `POST InterFace.do?method=login`，携带本轮 `pageInfo.loginToken`（如有），解析 JSON 结果。

门户 URL 的查询原文来自本次探测结果，不保存或硬编码旧的 IP、MAC、令牌等动态参数。`pageInfo` 请求体与 `getServices` URL 中的 `queryString` 只做一次 `encodeURIComponent`。登录字段 `userId`、明文 `password`、`service`、`queryString`、`operatorPwd`、`operatorUserId`、`validcode`、`passwordEncrypt` 按原页面调用方式做两次 `encodeURIComponent`。

当前门户的 `AuthInterFace.js` 还会读取 `pageInfo.loginToken`，在登录请求体中以 `loginToken=encodeURIComponent(loginToken)` 提交，令牌只编码一次。缺少该字段可能返回 `page expired, please login again`。程序每轮认证重新读取令牌，仅在内存中用于当前请求，不写入配置或日志；旧门户没有返回非空令牌时省略该字段。

## 页面编码与服务选择

页面解码顺序为 HTTP `charset`、HTML `meta charset`、严格 UTF-8、GBK 回退。`pageInfo` 返回值覆盖 HTML 隐藏字段。`serviceJson` 同时支持 JSON 字符串和数组。

设置值映射到服务显示项：`campus` 对应校园网、`mobile` 对应中国移动、`unicom` 对应中国联通、`telecom` 对应中国电信。实际提交值始终取本次 `getServices` 返回对象的 `serviceName`。找不到服务、未知适配器或需要运营商附加账号/密码时停止自动认证并提示人工处理。

## legacy RSA

当 `passwordEncrypt=true` 时，密码处理与页面 `RSAUtils` 保持一致：

1. 对密码连续执行两次 `encodeURIComponent`；
2. 将结果按字符反转；
3. 依据模数的 16 位 digit 高位计算分块大小；
4. 每两个字符按 little-endian 组成一个 16 位 digit；
5. 执行原始 RSA 模幂，不使用 PKCS#1 或 OAEP 填充；
6. 每个 digit 输出 4 位十六进制，多块用空格连接；所得密文作为登录字段值再次执行两次 `encodeURIComponent`。

指数或模数无效时认证明确失败，不回退到明文。测试向量由保存页面的原始 `security.js` 通过 Node.js 直接执行得到。

## 验证码与安全边界

`pageInfo.validCodeUrl` 非空或登录响应要求验证码时，返回 `CaptchaRequired` 与真实门户地址。应用应打开浏览器供用户完成认证；自动流程不尝试把浏览器验证码提交到另一套 Cookie 会话。

每次登录执行均创建并释放独立 `HttpClient`、handler 与 `CookieContainer`。每个请求的超时覆盖响应头和正文读取，调用方取消令牌覆盖完整序列。认证 POST 的 3xx 响应一律拒绝继续，因此不会跨源转发账号或密码。日志记录脱敏后的 origin+path、HTTP status 和响应长度，不记录账号、密码、Cookie、动态 query 或原始响应。

DNS、超时、HTTP 5xx 与临时系统错误标为可重试；凭据、服务、验证码、认证时段和参数错误不重试。
